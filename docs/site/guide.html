The A-to-Z developer guide

Every system, every API name, every file — from an empty folder to a deployed multiplayer game. All names match the SDK exactly (sdk/server/assemblyscript/cyg-server.ts and sdk/client/web/cyg.js).

01Project setup

ox-game init my-game && cd my-game

02Schema & state — the reactive core

You declare the network state once; the build compiles it into typed server classes plus a browser descriptor. Clients decode at join — no client codegen, ever.

// src/schema.ts
const Player = schema({
    pid: t.int64(), x: t.number(), y: t.number(),
    hp: t.int32(), score: t.int32(),
}, "Player");

export const State = schema({
    players: t.map(Player),          // collection (per-player entities)
    coinX:   t.number(),             // root scalars = world-level values
    coinY:   t.number(),
    phase:   t.int32(),
}, "State");

In the room, the pattern is always the same three lines:

// src/room.ts
import { GameState, Player } from "./openoxide.schema";

export class CoinRush extends Room {
    private s: GameState = new GameState();

    onCreate(max: i32): void {
        this.setState(this.s);                       // 1. bind the state
    }
    onTick(dt: f64): i64 {
        // ... mutate s.players / s.coinX ...
        return this.commitState();                    // 2. dirty-only delta out
    }
}

How the wire works: commitState() encodes only fields you changed (dirty tracking) into tagged TLV rows — a quiet room costs ~0 bytes. Clients receive a full snapshot on join and patches afterwards, decoded through the descriptor. The state is also what the console's AOI and the descriptors in out/cyg.schema.bin are built from.

03Room lifecycle hooks

Per-tick flow: inputs in → simulate → commitState(). dt is the tick delta in seconds (1/128 at 128 Hz) — always scale movement by it, never assume fixed values.

04Inputs — the 128 Hz movement lane

Movement input is special: it rides the unreliable newest-wins lane (a late packet is worthless). The client packs a small binary frame; the server reads it with InputReader.

Client side (web SDK)

// keys → one flag byte (W=1 S=2 A=4 D=8 …), aim as a normalized vector
let flags = 0;
if (keys.has("w")) flags |= 1;
if (keys.has("s")) flags |= 2;
if (keys.has("a")) flags |= 4;
if (keys.has("d")) flags |= 8;

// the movement packet: [flags u8][aimX f32][aimY f32] on the unreliable lane
const pkt = new DataView(new ArrayBuffer(9));
pkt.setUint8(0, flags);
pkt.setFloat32(1, aimX, true);
pkt.setFloat32(5, aimY, true);
room.sendUnreliable("input", new Uint8Array(pkt.buffer));

Server side

import { InputReader, Key, isHeld } from "./openoxide-server";

onInputPacket(id: i64, input: InputReader): void {
    const flags = input.readU8();
    const aimX  = input.readF32();
    const aimY  = input.readF32();
    if (isHeld(flags, Key.W)) { /* forward */ }
}

InputReader: readU8(), readF32(), readF64(), readI64(), hasRemaining(n) — cursor-based, never throws past the end you check. Key/KeyCode carry the standard constants; heldFlags(ptr,len) + isHeld(flags,key) decode packed key bytes. For physics-based movement, Physics.move(pos, vel, radius, dt) (see §6) applies wall-sliding kinematic motion in one call.

Rule: onInputPacket is the reliable path (fires, chats, RPC-shaped messages — things you cannot afford to drop). Per-tick movement stays on sendUnreliable. Never swap them.

052D physics — Rapier2D (host-side, native speed)

Physics runs in the host, not the guest: your room calls imports, the host steps the world. Guest cost is just the calls (~7k CCU/core @128 Hz — published conservative; measured higher with 100–200-player rooms).

import { Rapier2D, BodyType, Vec2 } from "./openoxide-server";

onCreate(max: i32): void {
    Rapier2D.init(0.0, 0.0);                       // gravity x, y (top-down: 0,0)
    this.playerBody = Rapier2D.createBody(BodyType.Dynamic, x, y);
    Rapier2D.addCircleCollider(this.playerBody, 14.0, false, 0.0, 0.0);
    //                                     radius  sensor
    this.coinBody = Rapier2D.createBody(BodyType.Fixed, 400, 250);
    Rapier2D.addCircleCollider(this.coinBody, 24.0, true, 0.0, 0.0);  // sensor = pickup
}

onTick(dt: f64): i64 {
    // move: velocity or impulses — your choice per game
    Rapier2D.setVelocity(this.playerBody, vx, vy);
    // Rapier2D.applyImpulse(this.playerBody, ix, iy);

    // pickup: sensor contact test
    if (Rapier2D.checkContact(this.playerBody, this.coinBody)) { /* score++ */ }

    Rapier2D.step(dt);                              // advance the world once

    const out = new Vec2();
    if (Rapier2D.getPosition(this.playerBody, out)) {
        p.x = out.x; p.y = out.y;                   // read back into state
    }
    return this.commitState();
}

2D arena geometry (walls, obstacles)

Two ways — both boot-loaded once, cloned into every room (never re-created per tick):

  1. arena_2d.json in the project folder: 
    { "arena_width": 800, "arena_height": 600,
  "obstacles": [ { "x": 100, "y": 300, "w": 20, "h": 400, "rotation": 0 } ] }
    boxes carry x/y/w/h (optional rotation radians); all become fixed colliders. Or arena_map.json — parsed as a 2D map when no arena_2d.json exists.
  2. Console upload: game → Project → Maps → upload the same JSON with format 2D arena. The active version reaches the server at boot (no SSH, no file copy) and new rooms spawn on a re-activated map live.

063D — kinematic Physics + Rapier3D

3D gives you two layers. Physics is the character controller layer: world geometry, wall-sliding movement, raycasts, lag compensation. Rapier3D is the rigid-body layer: balls, boxes, impulses — projectiles, debris, dynamic props.

Map geometry (choose one, loaded at boot)

# cook a GLB scene into an OXCL collision mesh (instant boot, baked statics)
ox-game cook map.glb arena.oxcl

# …or simple boxes: arena_map.json
{ "arena_width": 60, "arena_depth": 60,
  "obstacles": [ { "id": 1, "name": "wall", "x": 0, "y": 2, "z": -30,
                   "w": 60, "h": 4, "d": 1, "walkable_roof": false } ] }

Priority at boot: console-uploaded map (per game, active version) → local arena.oxcl → arena_map.json. Rooms clone the loaded world — spawn cost is milliseconds, geometry processing never repeats per tick.

Kinematic character movement (sky3d's pattern)

import { Physics, Vec3 } from "./openoxide-server";

onTick(dt: f64): i64 {
    // desired velocity from input, then one call moves + slides along walls
    const result = Physics.move(pos, vel, /*radius*/ 0.5, dt);
    // result: MoveResult { position, grounded … }

    // snap to floors / walk on ramps:
    const ground = Physics.getSurfaceHeight(pos, 0.5);

    // hitscan with lag compensation (rewinds to what the shooter saw):
    const hit = Physics.lagRaycast(origin, dir, 200.0);
    return this.commitState();
}

Physics surface: move / moveRaw (wall-sliding step), raycast / raycastRaw, lagRaycast, getSurfaceHeight, distance, checkCircleOverlap (XZ), checkSphereOverlap, isPointInSphere, isPointInBox. Vector-first: APIs take Vec2/Vec3, the *Raw variants are scalar escape hatches.

Rapier3D rigid bodies (projectiles, dynamic props)

import { Rapier3D, BodyType, Vec3 } from "./openoxide-server";

onCreate(max: i32): void { Rapier3D.init(new Vec3(0.0, -9.81, 0.0)); }

onTick(dt: f64): i64 {
    const bullet = Rapier3D.createBody(BodyType.Dynamic, spawnPos);
    Rapier3D.addBallCollider(bullet, 0.1);
    Rapier3D.setVelocity(bullet, new Vec3(dir.x * 60, dir.y * 60, dir.z * 60));

    if (Rapier3D.checkContact(bullet, targetBody)) { /* damage */ }

    Rapier3D.step(dt);
    const p = Rapier3D.getPosition(bullet);        // returns Vec3
    return this.commitState();
}
Full Rapier3D surface
init(gravity: Vec3) · createBody(BodyType, pos: Vec3) · addBallCollider(id, radius) · addBoxCollider(id, halfExtents: Vec3) · setPosition / setVelocity / getPosition / getVelocity · applyImpulse(id, impulse: Vec3) · checkContact(a, b) · removeBody(id) · step(dt)

Per-core physics capacity (measured sandboxed, 2-core/2 GB cgroup): Rapier3D 500-body rooms ≈ ~15k CCU @60 Hz published-safe (measured higher), ~7k+ @128 Hz. Physics is never the bottleneck — guest logic is.

07Navmesh — bot pathfinding

Bots ask the host for an any-angle path across the baked navmesh; you steer them along the waypoints. Nothing to compute in the guest.

import { NavMesh, Vec2 } from "./openoxide-server";

onTick(dt: f64): i64 {
    for each bot:
        if (reachedWaypoint || waypoints.length == 0) {
            waypoints = NavMesh.findPath(botPos, targetPos, /*maxPoints*/ 32);
            waypointIndex = 0;
        }
        // steer toward waypoints[waypointIndex], advance when close
}

Getting a navmesh in (two ways)

  1. Console upload: game → Project → Maps → format Navmesh → upload the baked file (Polyanya .nav2d/.mesh). The server loads the active version at boot and injects it into every room — sys_navmesh_find_path reads it inside NavMesh.findPath.
  2. It is also injected automatically when the map arrives with the game's uploaded assets — rooms created after the injection (or re-injected hot-reload) see it.

findPath returns corner waypoints — the start and goal are not guaranteed members of the list; steer point-to-point and treat the last point as "arrive". Unreachable targets return an empty path.

08AOI — area of interest

Register every moving entity once, query who is near — the host keeps the spatial index (kiddo r-tree) and your deltas stay small because clients only receive what matters.

// keep the index fresh (on join / on tick when moving)
spatialUpdate(playerId, new Vec2(p.x, p.y));
// 3D worlds / plain numbers:
spatialUpdateXY(playerId, x, y);

// who is within R units of me? → ids written into your buffer, count returned
const near = spatialQuery(new Vec2(p.x, p.y), 40.0, outIdsPtr);

// on leave — remove or the ghost lingers in everyone's queries:
spatialRemove(playerId, new Vec2(p.x, p.y));

The host's schema-AOI can also filter deltas automatically when your schema carries x/y fields and [aoi] enabled = true in config — entities outside a viewer's radius are not encoded for that viewer at all.

09RNG, timers, combat, match state

All deterministic, all rollback-safe — these never read wall-clock, so a replay re-simulates identically.

// deterministic RNG (per-room seeded from the room name)
rngNext(): f64                            // 0..1, xorshift64 — loot spawns, scatter
Random.seed(s: u64) / Random.nextU32()    // explicit control
clockTicks(): i64                         // the tick counter — time itself

// tick-based timers (Colyseus this.clock, but deterministic)
Timers.set(id, delayTicks, intervalTicks = 0)   // 0 = one-shot
Timers.poll()                                   // once per onTick → fired ids
Timers.cancel(id)

// combat: zone-weighted damage with crits
const dmg = Combat.applyDamage(/* attacker seed, zone, weapon … */);  // → DamageResult

// match flow machine + pickup/cooldown helpers
MatchStateMachine / CooldownTracker / TriggerZone

Timers are polled, not callbacks: call Timers.poll() at the top of onTick and switch on the returned ids. That is what makes them survive rollback replays.

10Messaging — broadcast, send, RPC

// server → everyone (reliable)
this.broadcast("phase", writerBytes);
this.broadcastText("chat", "welcome!");

// server → one player
this.sendTo(playerId, "private", bytes);
this.sendTextTo(playerId, "toast", "level up");

// ── request/response RPC (client asks, server answers) ──
this.onRequest("login", (senderId: i64, reader: InputReader, ctx: RequestContext) => {
    const name = reader.remainingBytes();          // read the payload
    ctx.replyText("ok");                            // or ctx.reply(bytes)
});
// 'request'/'response' are reserved names — onMessage never sees them.

// typed app messages from clients (reliable lane)
this.onMessage("chat", (senderId, reader, room) => { /* … */ });
Client callLaneUse for
room.send(type, data) / sendBytesreliable, orderedfire, hit, chat, score — cannot drop
room.sendUnreliable(type, data)newest-wins, no retransmitmovement/aim every tick
room.request(type, data, timeoutMs=5000)reliable + promiselogin, buy, match action — await reply

Server events (Fire/Hit/Scores) ride an ordered event lane with sequence numbers and SACK resends — a client that misses frame 12 gets exactly frame 12 again, nothing more. Lanes never block each other.

12Client SDK A-to-Z (web)

import CYG from "/openoxide-client.js";          // served by the control plane
const { Client, Callbacks, Storage } = CYG;

// ── connect ──
const client = new Client(SERVER_ORIGIN);        // control-plane origin
const room = await client.joinOrCreate("game_room", { mode: "duo" });
// also: client.join(name) · client.create(name) · client.joinById(id) · client.spectate(name)

// ── state (descriptor arrives on join; zero codegen) ──
room.onStateChange((state) => draw(state.players.get(room.playerId)));
const cb = Callbacks.get(room);
cb.onAdd("players", (p, id) => { /* spawn */ });
cb.onRemove("players", (p, id) => { /* despawn */ });
const stop = p.listen("hp", (value, prev) => bar(value));  // field-level, returns unsubscribe

// ── signals ──
room.onError((code, msg) => {}); room.onLeave((code) => {});
room.onReconnect(() => {});      room.onDrop(() => {});        // auto-reconnect is built in

// ── messaging ──
room.onMessage("chat", (payload) => {});
room.onMessage("*", (type, payload) => {});                    // wildcard
room.send("fire", { dir });  room.sendBytes("bin", u8);
room.sendUnreliable("move", u8);                               // newest-wins lane
const res = await room.request("login", { user });              // RPC, 5 s timeout

// ── accounts ──
await client.auth.login({ email, password });    // also .device .register .provider .gameCenter .instantGame

// ── helpers ──
Storage.set("muted", true); Storage.get("muted", false);      // localStorage, JSON, 'ox_' prefix
room.clock.now(); room.clock.setTimeout(fn, ms);               // server-clock aligned
room.ping((rttMs) => {}); room.leave(/*consented*/ true);

Server-side SDK (cyg-server.ts) mirrors every name you saw in §4–§10 — one mental model both ends. Generated interfaces exist for Lua/C/C++/Rust/C#/TS (ox-game gen-interface); native engines speak raw UDP with the same frames.

13Console operations

  • Games & Projects — register a game (minted game_key/api_key/client_key), open its workspace. Every view inside is scoped to that game; another game's telemetry is refused, not mixed.
  • Overview & Realtime — live CCU/rooms/tick-rate/tick-p99, tick-time trace, tick histogram, transport mix, queue depths. One live socket feed.
  • Project → Configuration — sync rate (Hz applies live, the running server retunes on the next tick), max players, persistent rooms, auto-close. Changes to status/engine switch relay↔WASM.
  • Project → Maps — upload/activate/delete per format (§11).
  • Project → WASM Modules — upload .wasm (+ source for audit), ABI gate names any missing export, activate/rollback with a live hot-swap — players stay connected.
  • Game Rooms / Matches — live rooms with member lists; terminate a match from the row.
  • Accounts — full BaaS surface; Ban revokes tokens instantly and kicks live sessions (matches left, socket closed) — not just "blocked at next login".
  • Players / Game Data / Monetization — accounts, groups, notifications, leaderboards, tournaments, storage, purchases, subscriptions — all filtered by the game you are in.

  • Secrets: real [control.session] signing keys + console credentials; the server refuses default secrets unless OX_ALLOW_DEFAULT_SECRETS=1 (dev only).

15Schema DSL — complete reference

Colyseus v5 syntax, fully compatible. File: src/schema/player.ts. The compiler reads the schema({...}, "Name") calls and generates the typed AssemblyScript binding (gen/cyg.schema.ts), the binary descriptor (out/cyg.schema.bin) and the browser contract (out/cyg.schema.d.ts).
