Overview Match Quest Tournament States Kaun kya bhejta hai

Normal match, quest aur tournament — kaise chalte hain

Har diagram ke saath Hinglish explanation. Golden rule: client progress/score khud nahi badhata — game server server-key se bhejta hai.

Ek line me: client seat leta hai aur room me khelta hai; quests events se progress karte hain; tournament ek time-window wala leaderboard hai jisme client join karke score likhta hai.

1. Overview — kaun kis se baat karta hai

1 · loginPlayer token leta hai.
2 · matchmake / list / claim / scoreSaari player HTTP calls.
3 · seat ticketControl plane seat JSON deta hai.
4 · state / inputClient room se realtime baat karta hai.
5 · events / resultsRoom ya game server counters bhejta hai.
Yaad rakho: matchmaking sirf seat deta hai. Asli khel room ke andar chalta hai.

2. Normal match

Steps

  1. Login → POST /v2/account/authenticate/device → token.
  2. Matchmaking → POST /matchmake/joinOrCreate/tank-3d with { name, skin }.
  3. Seat JSON → sessionId, reconnectionToken, gamePort, iceServers.
  4. Connect → wss://host/ws/signal?seat=token (WebRTC) ya WebSocket fallback.
  5. Room → onJoin, schema, state snapshot, input + state delta.
  6. Match end → room/host POST /v2/events ya POST /v2/match/{id}/result server-key se.
const room = await client.joinOrCreate("tank-3d", {
  name: "miya",
  skin: "ninja"
});

room.onStateChange((state) => draw(state));
room.onMessage("chat", (msg) => {});
room.sendInput({ moveX: 1, jump: false });

3. Quest

Flow

operator → POST /v2/console/quests     (definition)
server   → POST /v2/events             (counter +1)
client   → GET  /v2/quest              (list + progress)
client   → POST /v2/quest/claim        (reward)

Definition (operator)

POST /v2/console/quests
{
  "quest_key": "win-3",
  "title": "Win 3 matches",
  "goal_kind": "wins",
  "goal_amount": 3,
  "reward": {
    "currency": { "gold": 50 },
    "items": [{ "item_id": "medal", "quantity": 2 }]
  }
}

goal_kind = counter ka naam. Event ka name isi se match karna chahiye.

Progress (game server)

POST /v2/events
Authorization: Basic base64("<server-key>:")

{ "events": [
  { "user_id": "<player-uuid>", "name": "wins", "value": 1 }
]}

Server player_stat counter badhata hai, player_quest re-project karta hai, aur goal cross hone par quest.completed webhook bhejta hai.

Room mirrored events: sirf config me listed events +1 dete hain:
[gameplay] record_events = ["kill", "win", "match_end"]

List + progress

GET /v2/quest

{ "quests": [{
  "quest_key": "win-3",
  "goal_kind": "wins",
  "goal_amount": 3,
  "progress": 1,
  "state": "in_progress",
  "reward": { "currency": { "gold": 50 } }
}]}

Claim

POST /v2/quest/claim
{ "quest_key": "win-3" }

Server pehle quest row flip karta hai, phir reward deta hai — isliye double claim refuse hota hai.

Quest caveats: window + season gating, requires_product IAP check, quest chains/auto-claim abhi nahi, season reward_track auto-paid nahi.

4. Tournament

Tournament = time-window wala leaderboard. Bracket/knockout system nahi hai.

Operator create

POST /v2/console/tournament
{
  "id": "weekend-cup",
  "title": "Weekend Cup",
  "duration": 3600,
  "start_time": "2026-11-04T18:00:00Z",
  "join_required": true,
  "max_size": 1000,
  "max_num_score": 20,
  "authoritative": false,
  "rule_key": "ranked-eligibility"
}
FieldMatlab
durationround kitne seconds
start_time / end_timewindow
join_requiredpehle join zaroori?
max_sizekitne players
max_num_scorekitne score attempts
authoritativesirf server-key writes
rule_keyeligibility rule

Client flow

GET  /v2/tournament                     → tournaments[] + cursor
POST /v2/tournament/weekend-cup/join    → eligibility check
POST /v2/tournament/weekend-cup         → { score, subscore, operator }
GET  /v2/tournament/weekend-cup         → records[] sorted
GET  /v2/tournament/weekend-cup/owner/<uid>
DELETE /v2/tournament/weekend-cup       → apna record

Operators

operatorMatlab
1 / bestbest score rakho
2 / setreplace karo
3 / incrementadd karo
4 / decrementsubtract karo
Rule gating: rule_key set ho to join aur score dono par active rule player_stat ke against evaluate hota hai. Rule unpublished/unmet → 400, fail closed.
Authoritative board: player token se write → 403. Sirf game server/server-key lane se score.
